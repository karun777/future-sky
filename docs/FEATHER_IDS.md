# Feather identifiers

Adopted by Karun on 17 November 2026 for project documentation and coordination.

Write each feather as **PROJECT-Wn-Fm**. Use the uppercase project prefix, ASCII hyphens, the home wing number (1–8), and the positive feather number allocated by that project's register. Write decimal numbers without leading zeros. The title follows the ID and can change independently.

| Accepted prefix | Project |
|---|---|
| NL | Neptune Lounge |
| FS | Future Sky |
| MK | Maar Koodjal |
| ULE | Ultra Light Enterprises |

**Proposed additional prefix:** FNE for First Nations Enterprise. Proposal only, pending confirmation. Existing FNE records keep their local identities.

Use the complete ID in authored headings, indexes, templates, handovers, exports, diagrams and discussions. Write **NL-W7-F3 and NL-W7-F4** when identifying these two nodes. A range or list label is never itself an ID. A project-qualified wing such as MK-W5 is a wing reference.

One feather has one project, one home wing, one number and one lifecycle. Only its owning register allocates and counts it. A cross-wing or cross-project reference records a relationship or return. It confers no additional completion, authority, data access or automatic state change. Record the source and destination, what the link means, the evidence or revision, and the next decision.

Read older project-local Wn-Fm labels in their owning project's namespace unless the text identifies another project. In ambiguous imports, resolve the source before assigning a prefix. Existing filenames, links, historical quotations, evidence IDs, hashes, branches and pre-wing numbering remain valid locators. When editing an active record, use the qualified ID for display and keep the locator stable. This convention applies across the maintained document set and to future records.
