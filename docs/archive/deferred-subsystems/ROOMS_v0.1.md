# ROOMS.md

## Future Sky Room Production Standard

**Status:** Draft v0.1

A room is more than a location.

A room is a complete experiential package.

Every room should gradually evolve until it satisfies the following
production checklist.

------------------------------------------------------------------------

# 1. Identity

-   Room ID
-   Asset ID
-   Name
-   Era
-   Timeline
-   Region
-   Parent location

Example:

``` text
Room ID: dance_floor
Asset ID: TC-NL-DANCE
Era: Manzo
Region: Triton Central
Location: Neptune Lounge
```

------------------------------------------------------------------------

# 2. Narrative Purpose

Every room should answer:

-   Why does this room exist?
-   What emotions should it evoke?
-   What story does it advance?
-   Why will players return?

------------------------------------------------------------------------

# 3. Visual Identity

-   □ Background image
-   □ Thumbnail
-   □ Alternate room states
-   □ Event variants
-   □ Lighting notes

The visual should orient the player before they read.

------------------------------------------------------------------------

# 4. Sound

Every room has a sonic identity.

-   □ Ambient sound
-   □ Primary soundtrack
-   □ Optional playlist
-   □ Silence (if intentional)

Music is part of the architecture.

------------------------------------------------------------------------

# 5. Curation

Every room has a curator.

Curators select atmosphere rather than create every asset.

Record:

-   Curator
-   Curation notes
-   Guest curators
-   Seasonal variations

------------------------------------------------------------------------

# 6. Writing

A room description should:

-   Establish place
-   Create mood
-   Reward observation
-   Leave unanswered questions

Avoid walls of text.

Write with rhythm.

------------------------------------------------------------------------

# 7. Characters

Document:

-   Resident NPCs
-   Visitors
-   Encounter frequency
-   Portrait assets

People are as much a part of a room as its walls.

------------------------------------------------------------------------

# 8. Objects

List important objects.

For each object:

-   Name
-   Asset ID
-   Purpose
-   Interactions

------------------------------------------------------------------------

# 9. Thread Nodes

Document:

-   Arrival nodes
-   Narrative nodes
-   Discovery nodes
-   Repeatable nodes
-   Hidden nodes

A room should feel alive.

------------------------------------------------------------------------

# 10. Room States

Rooms are not static.

Examples:

-   Calm
-   Busy
-   Empty
-   Festival
-   Blackout
-   Comet proximity
-   Memory echo

The renderer selects the appropriate state.

------------------------------------------------------------------------

# 11. Gameplay

Document:

-   Commands
-   Discoveries
-   Secrets
-   Quests
-   Exits
-   Requirements

------------------------------------------------------------------------

# 12. Technical

Reference:

-   room.json
-   Asset package
-   Metadata
-   Music metadata
-   Image assets
-   Future renderer requirements

------------------------------------------------------------------------

# 13. Completion Checklist

A production-ready room should contain:

-   □ Identity
-   □ Narrative purpose
-   □ Description
-   □ Exits
-   □ Background artwork
-   □ Thumbnail
-   □ Ambient soundtrack
-   □ Curator
-   □ NPC roster
-   □ Object list
-   □ Thread nodes
-   □ Room states
-   □ Metadata
-   □ Technical references

------------------------------------------------------------------------

# 14. Design Principles

> A room is not a paragraph.

> A room is not an image.

> A room is not a soundtrack.

A room is the point where architecture, narrative, sound, art, code, and
player memory intersect.

If players remember a room years later, it has become more than
geometry.

It has become a place.
